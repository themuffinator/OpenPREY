# OpenQ4 Upstream Architecture Survey: fork point (abb9a688, 2026-02-18) → main (d41186e4, 2026-07-31)

575 commits. Project renamed `OpenQ4` → `openQ4`; releases advanced through **v0.9.0** (tag exists; `69b05a99` "prepare 0.9.0"). Meson project went from `0.0.1, c89/vc++latest, meson >=1.2` (effectively MSVC-only) to `0.1.010, c11/**c++20**, meson >=1.6, b_vscrt=static_from_buildtype`, building Windows (MSVC 19.46+/VS2026), Linux x64+ARM64 (GCC 13+/Clang 17+), and experimental macOS (Xcode 16+). Scale of engine churn vs fork point: `src/renderer` **278 files, +153,672/−41,034**; `src/framework` +26,726; `src/sys` +19,231; `src/sound` +5,490; `src/ui` +4,966; `src/idlib` +3,017; `src/cm` +1,578. The rest of the diff is dominated by `content/baseoq4/` assets (lightgrid bakes, loadscreens, GUIs, botfiles, fonts).

## (a) Renderer rewrite

The shipping default is still the OpenGL ARB2 path, but the renderer around it was rebuilt three times over and finally **moved behind a module boundary**:

- **Tiered modern-GL architecture** (`docs/dev/gl-renderer-modernization.md`): `r_glTier` ladder (`LegacyGL2Compat` → `ModernGL33/41`, `GpuDrivenGL43`, `LowOverheadGL45`, `TopGL46`, `NullRenderer`), an opt-in modern executor with an evidence-gated default-promotion contract (`r_rendererModernAutoPromote`, `r_rendererPromotionEvidence`), `r_renderer arb2` always kept as rollback. New front-end machinery: `ScenePackets.cpp`, `RenderGraph.cpp`/`RenderGraphResources.cpp`, `ModernGLExecutor/SubmitPlan/DrawPlan/ShaderLibrary`, `ModernClusteredLighting`, `ModernShadowPlanner`, `RendererUpload` (dynamic upload streams), `RendererMetrics` (GPU timer queries), `GLStateCache`, VBO pooling/index VBOs, redundant-state filtering (`r_useRedundantStateFiltering`).
- **Shader system: ARB2 remains the parity baseline; everything new is GLSL.** 65 shader files in `content/baseoq4/pak0/glprogs/`: bloom/HDR tone-map, SSAO, CRT, SMAA 1x (3-pass), lens flare, motion blur/vectors, resolution-scale HQ upscale, soft particles, lightgrid indirect, `material_interaction` (opt-in `r_enhancedMaterials` GLSL shading), cel outline, player outline/rimlight, and a full shadow-map suite (`shadow_interaction`, point/projected casters, translucent-moment casters, debug overlay). ARB validity reporting via `r_shaderReport`/`reportShaderPrograms`, `r_interactionColorMode` for interaction packing.
- **Shadow mapping** became a production feature (opt-in `r_useShadowMap`): CSM for projected lights, point-light cube maps as the default mapped path, a persistent projected-light shadow atlas with static/dynamic layering, hashed-alpha and translucent casters, budget degradation and telemetry — plan in `docs/dev/plans/2026-07-09-shadowmapping-production.md`, code in `ShadowMap*.cpp`.
- **Renderer modules (the Vulkan track's Phase B, Jul 16–17)**: the engine now binds only to `idRenderSystem`, a backend-neutral `glConfig`, and `glIndex_t`. `src/renderer/RenderModuleAPI.h` defines a versioned `GetRenderAPI` C ABI (currently **version 7**) mirroring the game-module handshake. `renderer-gl_<arch>` and `renderer-vk_<arch>` are built as dynamic modules, selected by `r_renderApi` with fail-closed fallback to GL; on Windows/Linux SDL3 the client **sheds the static renderer and loads `renderer-gl` by default**, and the dedicated server is GL-free (`0c9d76eb` "default flip, GL-free ded"). Window/input/display stays engine-side (SDL3); modules negotiate contexts through `renderWindowServices_t`.
- **`src/render_geo/`** — CPU render-geometry static library (TriSurf, shadow, interaction, light, polytope code) carved out in Phase B6 (`4fbab260`) so dmap in the engine and the renderer modules share it.
- **`src/imagetools/`** — shared image static library (BinaryImage, DXT, Color, jpeg-6, `Image_files/process/program`) carved out in Phase B2 (`04128897`), shared by the engine and both renderer modules.
- **Native Vulkan renderer** (`src/renderer/Vulkan/`, plan `docs/dev/plans/2026-07-16-vulkan-renderer.md`): Vulkan 1.3 (dynamic rendering, sync2, timeline semaphores), volk + VMA, implements only the packet/graph track (ARB2 is never ported). By head it renders menus, world (depth prepass + ambient), interactions, projected-light shadow atlas + point-light cube shadow maps, stencil shadow volumes, fog/blend lights (Phases C–G, `33ee887c`…`b471b4b5`); documented **experimental/opt-in** (`5e0ddeac`); MoltenVK-backed on macOS (`ffc96c71`).
- **MD5R**: support for Quake 4's packed binary model format — `Model_md5r.cpp`, MD5R/MD5RProc companion export+load commands, primBatchMesh packed direct-draw and packed shadow volumes, per-batch joint palettes, binary `.proc` and binary collision-model files (`6a08ab1a`), `Q4SDK_MD5R` gating (`29c9c262`).
- Also new: TrueType font renderer (`tr_fontTTF.cpp`, default on, `docs/dev/ttf-font-system.md`), lightgrid irradiance with pre-baked per-map textures and `.lightgridpack`, high-framerate presentation, FPS overlay modes, RenderDoc capture workflow (`src/framework/RenderDoc.cpp`).

## (b) Gamelibs split

- **`4ff3d848` (2026-03-06) deleted `src/game` from the tree.** Game code lives in the companion repo **openQ4-game** (renamed from OpenQ4-GameLibs, `dde49903`), expected at `../openQ4-game` or via `OPENQ4_GAMELIBS_REPO`. Rationale: cleanly separate Quake 4 SDK-EULA-licensed code from the GPLv3 engine.
- At configure time, `tools/build/stage_gamelibs.py` stages `src/game` (SP) and `src/mpgame` (MP) into `.tmp/gamelibs_stage/` and writes a hash/git-state manifest; Meson refuses to build without it. Output is **two modules**: `game-sp_<arch>` and `game-mp_<arch>` installed into `baseoq4/` (fork point had a single game module).
- The engine keeps the `GetGameAPI` handshake in `framework/Common.cpp` plus `GameModuleDiagnostics.h`; **`GAME_API_VERSION` is now defined in the staged game headers, not the engine tree**. Savegame payloads embed a GameLib source-snapshot stamp (see (g)). Mods may be content-only: module lookup falls back to `baseoq4/`'s modules.

## (c) bse_api → in-tree BSE

- Fork point: `src/bse_api/` thin interface + prebuilt closed `OpenQ4-BSE_<arch>` dynamic libraries shipped in `.install/`.
- `2c75a5d5` (Mar 19) made the BSE runtime mandatory; `9c1989fd` (same day) **integrated full BSE sources in-tree at `src/bse/`** (`BSE.h`, `BSE_Effect`, `BSE_EffectTemplate`, `BSE_Envelopes`, `BSE_Manager`, `BSE_Particle*`, `BSE_Module`…) and deleted the external runtime/binaries and `bse_api`. BSE is statically linked into the client; the ded keeps a stub path.
- Follow-ups: retail sprite-particle quad parity (`e63472d4`), effect frustum culling on by default (`43a97155`), immediate-expiry freeing in the renderer (`05669098`), soft-particle depth fade (`r_softParticles`). Research/parity doc: `docs/dev/quake4-bse-research-and-implementation-plan.md`.

## (e) Filesystem / framework modernization

- **Asset validation**: official `q4base` PK4 checksum validation at startup (`fs_validateOfficialPaks`, `docs/dev/official-pk4-checksums.md`); retail game-binary PK4s (`game000.pk4`…, `gamex*.pk4`) are ignored since openQ4 ships its own modules (`be655d1b`, `d51aac02`); optional patch/language paks allowed (`67542718`). Steam/GOG/Flatpak auto-discovery incl. `libraryfolders.vdf` (`9828d3e2`).
- **`mod.json` mod manifests** (required for runnable mods, checked against `requiredopenQ4Version`; `FS_ParseModManifest` in `FileSystem.cpp`), mod-menu gating, MP auto-restart mod switching.
- **Own-content pipeline**: runtime content authored in repo `content/baseoq4/pak0|pak1` and built into `pak0.pk4`/`pak1.pk4` (`2e1d2cdb`); pak manifest (`3a1b576f`); `.install/` is generated staging. Load-priority and addon-parsing fixes (`2cf19eda`, `2c10d91f`); generated-image cache restored for fast level loads (`089331a6`) plus dedicated load-time passes (`89c58292`, `9adb69a3`).
- **Decl system**: `DeclPDA.cpp/.h` added engine-side; a full parity audit against decompiled retail Q4 (`docs/dev/retail-q4-decl-parity-audit.md`) drove many parser/defaulting/media-touch fixes (AF content masks `vehicleclip/flyclip/itemclip`, packed-writer policy, playback finish, etc.); declManager file methods exposed (`96da463d`). - **Savegames — format changed**: `SAVEGAME_VERSION` 1 → **1834** with retail `"Quake4"` header naming plus legacy openQ4 markers (`framework/licensee.h`); engine owns header/screenshot/staged atomic commit; game payloads carry format marker+version, engine build number, **GameLib source-snapshot stamp + file count**, class-boundary sync markers, and a footer; full preflight validation before `ExecuteMapChange`; sound-world serialization hardening (`docs/dev/savegame-reliability.md`; `ab725f55`, `ffa75b5f`, `fbeff719`, `b2fc6929`).

## (f) Platform / sys

- **SDL3 is the default backend on all platforms** (`platform_backend=sdl3`); `legacy_win32` is transitional, `native` is Linux GLX or comparison-only macOS Cocoa. Linux is Wayland-first with optional X11 (`83a59ecf`, `a635c622`, `linux_x11` option, libdecor validation in CI). Windows defaults to borderless windowed (`341c2c39`). Splash screens, display-aware resolution selection, multi-monitor `r_screen`, high-DPI mouse, SDL gamma/brightness.
- **Steam Deck**: dedicated launcher/profile (`com_platformProfile steamdeck`), controller menu integration, gyro/touchpad settings (`67eef801`), QA docs. Full controller support: hotplug, curves, rumble, southpaw.
- **macOS**: huge June–July effort — SDL3 packaging, signing/notarization with unsigned fallback, Apple GL2.1 containment (VBO disabled `073d0a29`, simple ARB interaction `be5c5ef1`), `apple_framework` OpenAL provider policy, MoltenVK Vulkan module; status **experimental**, governed by ~20 `docs/dev/macos-*.md` policy docs.
- **Linux ARM64**: cross builds + CI assetless smoke tests, `preview` support tier with an evidence-gated `first-class` release path; AAPCS64 varargs fixes (`d8a2051e`), arm64 machine-quality tiers (`2709cf57`, `d495e61a`).
- **Windows**: static MSVC CRT (`c9a97d17`), VS2026 baseline, thread-registry serialization (`30ee5e13`), modernized init (`88f9f625`); POSIX single-instance lock (`9782cc2d`); `CLOCK_MONOTONIC` (`d7d3915d`).
- **Sound**: OpenAL device selection/monitoring/fallback-to-silence (`fbdd999e`, `a9601ceb`), HRTF option (`b648aa1f`), velocity/Doppler (`c0d1ed2a`), retail attenuation/volume/pitch alignment (`2dd80ebe`), retail sound ABI restored (`f0b51cfa`); a newer voice-handling experiment was reverted to the June-23 baseline and left opt-in (`76a63d02`, `175c8cfd`, `874e7d3b`).

## (g) Everything else a downstream fork must know before rebasing

1. **Whole-tree mechanical churn** that will conflict everywhere: lowercase include-case normalization (`0cdcd44d`, e.g. `Licensee.h` → `licensee.h`), the global UTF-8 re-encode (`360b4703`), and `OpenQ4`→`openQ4` branding normalization (`3eec101a`, `cb379c48`). Treat as one rebrand/normalize layer.
2. **Repo layout moved**: assets now under `content/baseoq4/pak0|pak1` (gamedir renamed twice: `openbase`→`openq4`→`baseoq4`); docs split into `docs/dev` + `docs/user`; heavy build tooling in `tools/build/` (`meson_sources.py` generates source lists — file lists are no longer hand-maintained in meson.build).
3. **The engine no longer contains game code** — any fork carrying game sources in-tree (as openPREY does with `src/Prey` + `src/game`) must either adopt the companion-repo staging model (`stage_gamelibs.py`, `OPENQ4_GAMELIBS_REPO`) or re-wire `build_games` to in-tree paths. SP/MP are now **separate modules** (`game-sp_*`/`game-mp_*`).
4. **Renderer is a module** (ABI v7 in `RenderModuleAPI.h`); engine↔renderer coupling was deliberately severed (no GL typedefs in renderer headers, window state split from `glConfig`, `imagetools`/`render_geo` static libs). Any downstream renderer patches (openPREY touches `tr_*`, `draw_common`, `Image_*`, `RenderWorld_*`) land in a tree that was rewritten several times (May "New renderer" phases, June rework 2 + 66-fix audit, July module split) — expect this to be the hardest part of the rebase; upstream renderer diff is ~150k added lines.
5. **Format/ABI changes**: `usercmd_t` buttons byte→short + impulses to 127; `SAVEGAME_VERSION` 1→1834 with stamped, preflight-validated payloads; new `.mvd` demo format and demo menu; `GAME_API_VERSION` defined in the companion repo; renderer module ABI versioning rejects mismatched layouts.
6. **BSE is now mandatory, in-tree, and client-linked** (`src/bse`), replacing the fork-era `bse_api` + prebuilt DLL arrangement openPREY inherited.
7. **Behavioral defaults changed**: TTF fonts default on, borderless windowed default (Windows), BSE frustum culling default on, generated image cache, SSAO default off (`cd76b14b`), OpenAL "pre-plan" compatibility path default.
8. **CI/validation is now load-bearing**: commit-validation and push-verification workflows run renderer tier self-tests, assetless ARM64 renderer bootstrap, sanitizer lanes, headless-Weston Wayland cases, package validation; releases are gated on evidence records (Linux ARM64, macOS signoff).
9. **Directly relevant to openPREY**: upstream `TODO.md` ends with *"Project may benefit from catering towards multiple idTech4 titles, to include: Doom 3, Doom 3: BFG, Prey, ETQW"* — upstream is at least contemplating multi-title support, which could make some downstream divergence upstreamable.
