# openPREY 0.0.1

## Highlights

- Rebased the project onto the current OpenQ4 engine foundation while preserving openPREY as a Prey (2006)-focused engine and game-code replacement.
- Unified single-player and multiplayer around one `basepr/game_<arch>` module built from the canonical OpenPrey-game companion sources.
- Added deterministic `pak0.pk4` and `pak1.pk4` assembly for openPREY-owned runtime content, with development-only fixtures kept out of release packages.
- Updated Windows and Linux x64 validation, release packaging, launch profiles, icons, documentation, and product metadata for openPREY.

## Upgrade Notes

- Keep the whole package together and replace older openPREY binaries and the `basepr/` overlay as one set.
- Do not copy retail Prey PK4 files into `basepr/`; leave the original assets in the retail installation's `base/` directory.
- Developers must check out [OpenPrey-game](https://github.com/themuffinator/OpenPrey-GameLibs) beside this repository or set `OPENPREY_GAMELIBS_REPO` before configuring Meson.

## Change Log

- Engine binaries are named `openPREY-client_<arch>` and `openPREY-ded_<arch>`.
- The canonical game source trees (`game`, `Prey`, and `preyengine`) are staged directly from OpenPrey-game and compiled against this engine checkout's headers.
- Split `game-sp` and `game-mp` build artifacts have been replaced by the unified Prey module.
- Runtime content and manifests now use the sole `basepr/` namespace.
- VS Code launch profiles force windowed mode for safe automated validation.

## Current Limitations

- Full campaign and multiplayer parity are still under validation.
- macOS and additional architecture release workflows remain gated until their unified-module ports and runtime evidence are complete.
