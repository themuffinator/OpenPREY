## Upstream summary
Upstream OpenQ4 evolved massively in these paths (148 files, ~47.5k insertions) and — critically — much of openPREY's early sys/build work was upstreamed by the same maintainer and then extended far beyond it, so a large share of openPREY's fork-era changes are already present upstream in better form. Key architecture shifts that affect reapplication: (1) meson.build grew from ~300 to 1780 lines: native windows/linux/darwin host support, SDL3 backend on ALL platforms (default), 'native' backend choice per-OS, c11/c++20/b_vscrt=static_from_buildtype defaults, generated version metadata via tools/build/openq4_version.py, optional renderer-gl/renderer-vk shared modules (Vulkan track, commits 8bcdcdbf..d41186e4), Windows OpenAL32.dll install, icon/desktop-entry install loop identical in shape to openPREY's (assets/linux/openq4.desktop.in + Steam Deck variants, meson.build:1638-1715). (2) Game-libs model rewritten: sync_gamelibs.ps1 is now a deprecated no-op; game sources live in the companion openQ4-game repo and are staged at configure time by tools/build/stage_gamelibs.py into .tmp/gamelibs_stage (manifest + hashing); game-sp_/game-mp_ shared_modules are built in root meson.build from the staged tree with vs_module_defs (Game.def/mpgame.def), linux_game_module.map / darwin_game_module.exp export lists, and stage_direct_run_game_module.py; src/game no longer exists in the engine repo. (3) src/sys: new cross-platform src/sys/sdl3/sdl3_backend.cpp (5962 lines) — src/sys/win32/win_sdl3.cpp is now literally '#include "../sdl3/sdl3_backend.cpp"'; new posix_syscon.cpp, linux_sdl3.cpp, macosx_sdl3.cpp/macosx_sdl3_main.cpp/macosx_native_gl.h, sys_console_theme.h (win_syscon.cpp rewritten around a theme system, commit 8632851a); macosx_compat.mm exists upstream at 1089 lines (superset of openPREY's 369); MoltenVK Vulkan on macOS (ffc96c71). Upstream sys_public.h already has intptr_t _alloca16, arm64/x64 CPUSTRING for win/linux/macos, ID_INLINE_EXTERN, intptr_t Sys_DLL_* (posix too), sys_local.h StartProcess platform split, DXGI-based Sys_GetVideoRam (Sys_QueryDXGIVideoRamMB, win_shared.cpp:277), and focus-based audio muting (s_muteUnfocused in Session.cpp wired to Sys_SDL_IsGameWindowFocused / win32 Sys_IsGameWindowFocused). (4) CI: nightly-builds.yml was DELETED upstream (commit e78a6dfa); replaced by manual-release.yml (2408 lines), push-verification.yml, commit-validation.yml (1243 lines), discord-release.yml, linux-arm64-cross.yml and three macOS lanes; generate_nightly_changelog.py is now a shim delegating to generate_release_changelog.py. (5) tools/build gained ~30 scripts (stage_gamelibs.py, package_linux_appimage.py, build_windows_installer.py, assemble_macos_universal2.py, verify_*, generate_release_docs.py, windows_runtime.py, prepare_windows_openal.ps1, sync_icons.py, ...); package_nightly.py grew ~3.9k lines; meson_setup.ps1/.sh grew ~750/540 lines. (6) .vscode: tasks.json delegates to new .vscode/meson-task.ps1; launch.json grew ~5.2k lines of upstream configs. Net effect: prefer upstream wholesale for src/sys portability/macOS/SDL3/console work; the surviving openPREY value is Prey-specific (unified game module, Prey sync sources, LGLCD hooks, branding, Prey launch configs, Prey packaging identity) and must be re-expressed against the new staging/release architecture.

## Notes
Cross-cutting observations for the rebase planner: (1) A striking amount of openPREY's fork-era sys/build work (multi-platform meson, macOS modernization, DXGI vram, focus muting, intptr_t/arm64 portability, icon/desktop install, /BASE:0x180000000, c11/c++20/static-CRT) was upstreamed into OpenQ4 by the same maintainer and then extended — for src/sys the rebase should take upstream files wholesale and re-apply only Prey identity (branding, save paths, LGLCD, CPU_EASYARGS question) on top. (2) The two genuinely hard items are the game-module/build pipeline (unified Prey game_<arch> module + src/Prey|src/preyengine sync vs upstream's stage_gamelibs.py companion-repo staging with sp/mp targets, export maps and Game.def handling) and CI/release (upstream deleted nightly-builds.yml in favor of manual-release/push-verification/commit-validation; openPREY's nightly release flow has no merge base). (3) basepy/meson.build (game module target + asset install subdir) is referenced from root meson.build via subdir('basepy') and belongs with the unified-game-module change even though it sits outside this task's path list. (4) Upstream's renderer is now optionally built as renderer-gl/renderer-vk shared modules gated by build_renderer_gl/vk options and r_renderApi selection — any Prey renderer changes (beam renderer etc., other subsystems) will interact with that module split when the engine meson targets are re-derived. (5) Working tree state: src/sys/win32/rc/OpenPreyVersion.rc was deleted and replaced by untracked src/sys/win32/rc/openprey_version.rc in uncommitted work; upstream meanwhile generates version metadata via tools/build/openq4_version.py into a header consumed by its rc — the openPREY version rc should be rebuilt on that generated-header model during the rebrand pass.
