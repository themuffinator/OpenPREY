## Upstream summary
Upstream restructured everything in these paths since the fork. (1) Content packaging: fork-era top-level openbase/ was renamed openbase->openq4 (c776256b), then relocated into content/baseoq4/{pak0,pak1} pak folders (c5ad9a27); all installed assets were deleted from .install (17393ed9 — .install now holds only OpenQ4 icons); pak0.pk4 is now assembled at build time via a manifest-driven custom_target (root meson.build:212-251, tools/build/build_pak0.py, pak manifest hardening in 3a1b576f) and the game dir carries a mod.json manifest (content/baseoq4/mod.json.in) consumed by a new in-game mod-details UI. content/baseoq4/meson.build now builds SPLIT SP/MP game modules (game_sp/game_mp, separate source lists, macOS dylib naming) instead of one module with install_subdir loose files. (2) Shader contract rewritten: pak0/glprogs grew from 4 files at fork to 66 GLSL programs — 4-stage bloom (extract/downsample/blur/composite), ssao, crt, hdr_luminance, 3-pass GLSL SMAA (smaa_edge/weights/blend .fs/.vs replacing the fork-era openq4_smaa_*.vfp ARB programs), soft_particle, motionblur/motionvectors, celoutline, lensflare, player_outline/rimlight, resolutionscale, lightgrid_indirect (124->323 lines), blur.fs (37->122), plus a full shadow-mapping suite. postprocess_openq4.mtr expanded 89->218 lines and material names dropped the openq4_ prefix (postprocess/openq4_black -> postprocess/black, new smaa_edge/weights/blend, blur, casupscale stages). Feature cvar names (r_bloom*, r_crt*, r_ssao*, r_hdr*, r_postAA) match the names openPREY's menu binds, with many new additions upstream. (3) Aspect expansion: upstream now has an engine-side loading-background composer (Session.cpp Session_PrepareExpandedLoadingBackground: resolves _left/_right/_top/_bottom sibling images and writes a composed guis/assets/generated/loadscreens TGA) plus ui_aspectCorrection (src/ui/UserInterface.cpp) and 16:9 cinematic bars (2eb9f17a); guis/loading/generic.gui uses gui::loading_bkgnd/canvasfill/virtual_screen_x|y_expand — the same contract openPREY's loading.gui already speaks a superset of. (4) Strings: pak0/strings/<lang>_openq4.lang (273 entries, #str_41xxx) covers the same advanced-rendering menu labels openPREY defined as #str_122xxx in its 999.lang packs. (5) Docs: docs/dev/ and docs/user/ were deleted and merged into docs/dev + docs/user (8533a68e), docs/dev/legacy deleted (5a90f72c); ~283 doc commits added shadow-mapping, macOS, Steam Deck, multiview-demos guides; docs/user/display-settings.md now itself documents r_mode -2 native-resolution fullscreen. (6) assets/: icon set renamed/expanded (assets/icons/quake4.* incl. 1024/512/40/20 px), Linux desktop entries gained version substitution and a Steam Deck variant (assets/linux/openq4-steamdeck.desktop.in), plus assets/docs/README.html, assets/release/README.html, assets/splash/quake4_rt_bitmap_4001.bmp. 177 upstream commits touch asset paths total.

## Notes
Key cross-subsystem couplings discovered while auditing the asset side: (1) src/renderer/draw_common.cpp hardcodes the openprey_* GLSL filenames (lines 774, 1023-1092, 1695) — the shader-mirror disposition (assets-02: adopt upstream's newer pak0/glprogs) requires the renderer rebase to either drop the openprey_ prefix or rename upstream files; upstream's postprocess material names also dropped the openq4_ prefix (postprocess/black etc.), which the renderer references. (2) Upstream's loading-background composer (Session.cpp) supersedes openPREY's per-side gui-param mechanism; openPREY's Session/ui changes for 332e5166 should be dropped in favor of the upstream implementation, keeping only the Prey art. (3) Upstream's mod.json manifest + pak0 build pipeline is the biggest structural shift for basepy/ — the whole basepy tree should be evaluated for relocation to content/basepy/{pak0,...} during the rebase. (4) The openPREY menu binds cvar names that still exist verbatim upstream, so the Prey GUI suite ports with low risk; only string IDs (#str_122xxx vs upstream #str_41xxx) need reconciliation. (5) .install currently double-tracks the pre-rename openprey/ copy alongside basepy/ plus committed binaries — dead weight that should be dropped regardless of the rebase. Working-tree (uncommitted) state was included: deletions of .install root binaries/icons and untracked .install/base, .install/basepr, and preymenu WIP assets confirm the .install tree is churning local state.
